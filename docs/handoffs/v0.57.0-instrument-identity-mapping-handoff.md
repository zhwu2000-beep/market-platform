# v0.57.0 Instrument Identity and Mapping Foundation Handoff

## Status

The implementation is on
`feature/v0.57.0-instrument-identity-mapping`, remains uncommitted and
unreleased, and leaves package version `0.1.0` unchanged.

## Public API and Schemas

`market_platform.instruments` exports canonical, external, and mapping-source
identities; `InstrumentMapping`; `InstrumentResolution`;
`resolve_instrument_mapping`; and narrow validation, mapping-outcome, and
correspondence errors.

Fingerprint schemas are exactly:

- `canonical_instrument/v1`;
- `external_instrument_identity/v1`;
- `instrument_mapping_source/v1`;
- `instrument_mapping/v1`.

`instrument_resolution/v1` is a bounded projection schema with no fingerprint.
Canonical IDs, resolver collections, and errors also have no fingerprints.

## Identity Grammars and Limits

Canonical IDs match `[A-Za-z0-9][A-Za-z0-9._-]{0,127}`. They are opaque,
case-sensitive, caller-supplied, and are not normalized or generated.

Canonical descriptors retain an exact released `TradingInstrumentIdentity`,
support only `equity` and `etf`, and require `[A-Z]{3}` trading currency.
Descriptor fingerprints cover the ID, complete released identity including its
fingerprint, asset class, and currency. One stable ID may have multiple
immutable historical descriptor fingerprints.

External namespaces match `[a-z][a-z0-9._-]{0,63}`. External symbols are exact
case-sensitive visible ASCII up to 128 characters; optional venues follow the
same policy up to 64 characters. No splitting, guessing, or vendor behavior is
attached to these passive values.

Mapping-source IDs and versions are visible ASCII without whitespace, bounded
to 128 and 64 characters. The optional configuration fingerprint uses the
repository lowercase SHA-256 contract. Source identity records provenance but
does not claim authentication.

## Mapping and Fingerprint Contract

Mappings retain complete typed external, canonical, and source identities plus
`valid_from` and optional `expires_at`. Timestamps are truly aware and
physically canonical UTC. Applicability is `[valid_from, expires_at)`;
`expires_at=None` is open-ended.

The mapping fingerprint covers its schema, each complete nested projection and
fingerprint, and canonical timestamp text. There is no confidence, priority,
note, method, metadata, provider payload, credential, account, broker, or risk
field.

All `to_dict()` outputs are bounded, deterministic, and recursively JSON-safe.
The resolution projection owns only the exact external identity, chosen
mapping, and canonical UTC `resolved_as_of`.

## Resolver Classification

`resolve_instrument_mapping(external_identity, mappings, as_of)` validates exact
types, canonical state, and an explicit aware time. `mappings` must be an exact
built-in `list` or `tuple`; subclasses, arbitrary sequences or iterables,
generators, sets, mappings, strings, and bytes are rejected before iteration.
This concrete finite-container contract prevents hostile or infinite custom
iteration. The resolver copies either accepted container to an immutable tuple,
sorts by mapping fingerprint, and rejects repeated mapping fingerprints.

- no exact external-identity record: `InstrumentMappingNotFoundError`;
- exact records but none active: `InstrumentMappingInactiveError`;
- multiple active records with the same ID and descriptor fingerprint:
  `InstrumentMappingAmbiguousError`;
- multiple active records differing in ID or descriptor fingerprint:
  `InstrumentMappingConflictError`;
- one active record: validated `InstrumentResolution`.

Results and bounded error details are input-order-neutral. The resolver never
chooses first, ranks sources, applies priority, prefers newest, partially
matches, normalizes external case, or guesses from symbol text.

`CanonicalInstrument` independently reconstructs every retained released
`TradingInstrumentIdentity` through its public constructor. Exact runtime type,
schema, symbol, venue, fingerprint, and complete projection equality are
required. A self-consistent fingerprint over fabricated noncanonical fields is
not sufficient.

## Compatibility and Boundaries

The released `TradingInstrumentIdentity`, trading signals, Order Intents, v0.56
application requests, codecs, services, projections, and fingerprints are
unchanged. `market_platform.instruments` imports only the public released
trading identity and canonical fingerprint function; trading and application
do not import the new package.

There is no application mapping operation, external codec, registry,
persistence, global cache, provider or broker access, TradingView/HTTP behavior,
authentication, account or snapshot state, risk, execution, CLI, Agent, or UI.
Future orchestration resolves an external identity and passes the retained
released trading identity into the existing v0.56 boundary while keeping
mapping provenance separate.
