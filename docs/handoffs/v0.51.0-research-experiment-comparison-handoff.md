## Release Status

## Scope

V0.51.0 adds deterministic in-memory structural comparison for one verified
baseline Historical Replay Artifact and one or more ordered verified candidates.
It does not execute Replay, load files, persist experiments, or calculate
investment-performance metrics.

## Schemas and Policy

- experiment: `historical_replay_experiment/v1`;
- comparison policy: `historical_replay_comparison_policy/v1`;
- pairwise comparison: `historical_replay_comparison/v1`.

The fixed policy requires exact symbol, interval, dataset content fingerprint,
ordered evaluation timestamps, and ordered observation fingerprints. It performs
one baseline-to-candidate comparison for each ordered candidate, aligns strategies
by ID plus occurrence index, and retains changed-step detail with complete
aggregates. It never intersects or unions timestamps and makes no causal claim.

## Public API

- `HistoricalReplayExperimentSpecification`;
- `HistoricalReplayComparisonCompatibility` and ordered reason enum;
- `HistoricalReplayComparisonResult`;
- `HistoricalReplayComparisonSummary`;
- `HistoricalReplayExperiment`;
- typed changed-step, state, execution, strategy-key, strategy-difference, and
  strategy-summary values;
- `compare_historical_replay_artifacts()`;
- `create_historical_replay_experiment()`.

Core APIs accept verified `HistoricalReplayArtifact` values only. Filesystem
loading remains in the v0.50 Artifact adapter.

## Identity

The experiment fingerprint covers the fixed policy, baseline run/result
fingerprints, ordered candidate indices and run/result fingerprints, and
caller-supplied comparison `SoftwareRevision` including its dirty flag.

Each pairwise comparison fingerprint covers policy, experiment/member identities,
compatibility facts, deterministic execution differences, the compatible summary,
and every retained changed-step record. Paths, labels, Artifact bytes/checksums,
wall-clock time, rendering, and runtime duration are excluded.

## Compatibility and Differences

Valid incompatible pairs return all applicable reason codes in fixed policy order.
They retain safe execution-level differences but contain no aligned state/strategy
detail and no misleading aggregate.

Provider is reported, not independently rejected. Because current observation
fingerprints include provider identity, a provider change ordinarily produces an
observation mismatch even when dataset contents match.

State comparison covers directional, trend, momentum, volatility, structure,
quality, and missing-input fields, with separate provenance and evaluation-evidence
indicators. Strategy comparison covers version/configuration identity, status,
rationale, required/missing inputs, typed evidence, provenance, and added/removed
members.

Strategy IDs align with a zero-based occurrence index per ID. Candidate reordering
does not destroy logical alignment, duplicate IDs remain distinct, and collection
order differences remain visible in execution provenance.

Typed comparison projections preserve null, boolean, integer, float, string,
datetime, enum, mapping, and ordered-sequence semantics for evidence, provenance,
and supporting state content. Boolean, integer, and float values remain distinct;
all finite floating zero representations canonicalize to `0.0`. Mapping insertion
order is neutral.

Summary strategy field-change counts are per aligned step/member comparison.
Added/removed member counts are unique aligned member keys. Per-member status
distributions use the stable enum order and changed-step counts use the common
evaluation timestamp denominator.

Public compatibility, summary, changed-step, result, and experiment constructors
validate every locally derivable invariant. Detail-derived counts share the same
canonical aggregation helper used by normal generation. Experiment construction
recomputes each pair through the canonical private builder, so a fabricated
comparison cannot be attached to otherwise correct member fingerprints.

## Compatibility Guarantees

- `run()`, `run_with_specification()`, and `run_execution()` are unchanged.
- Historical Replay Artifact schemas, deterministic bytes, loading, and integrity
  remain unchanged.
- `HistoricalReplayResult.to_dict()` and CLI schemas remain unchanged.
- Existing run, result, observation, dataset, specification, strategy
  configuration, Research, and benchmark fingerprints remain unchanged.
- Comparison imports no Replay service or Artifact filesystem adapter and creates
  no files.

## Limitations and Non-Goals

The comparison is structural and non-causal. It does not compare returns, P&L,
alpha, Sharpe ratio, drawdown performance, portfolios, orders, fills, execution
quality, or statistical significance.

Excluded: durable experiment serialization, member paths, embedded Artifacts,
Replay batches, parameter grids, optimization, intersection/union alignment,
provider-neutral observations, CLI, databases/cloud, UI, agents, workflows,
parallelism, resource limits, Research migration, and package-version changes.

V1 holds changed detail in memory and is intended for trusted-size locally loaded
Artifacts.
