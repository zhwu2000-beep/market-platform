## Delivered contract

The execution-planning package preserves all prior twenty-three exports and
adds exactly `BROKER_NEUTRAL_ORDER_SPECIFICATION_SCHEMA`,
`BrokerNeutralOrderSpecification`, and
`construct_broker_neutral_order_specification`, for twenty-six exports.

The keyword-only factory requires exact instruction, canonical instrument,
style choice, conditional price choice or explicit `None`, TIF choice, and
session choice. The frozen/slotted/`init=False` model exposes exactly those six
nested sources plus derived schema and fingerprint.

Schema is `broker_neutral_order_specification/v1`. Its fingerprint payload
covers schema, instruction fingerprint, canonical-instrument fingerprint,
style-choice fingerprint, price-choice fingerprint or exact null, TIF-choice
fingerprint, and session-choice fingerprint exactly once. Execution planning
has exactly seven fingerprint families.

## Correspondence boundary

Direct construction is prohibited. The private token is one per-instance
construction attestation used as an identity handle. A private module-closure
registry owns an immutable tuple-backed origin record for the exact
specification identity and anchors the original attestation, constructor-state
tuple, binding tuple, and all six source references. Retained and attestation
attributes must match those exact registered objects; replacement, mutation,
reconstruction, and cross-instance substitution are rejected.
Constructor-state elements are exact-type checked before equality. The registry
uses weak owner identity and exact-reference cleanup, is process-local, and is
absent from the public projection and fingerprint. This is correspondence
hardening, not cryptographic authenticity.

The canonical instrument is independently reconstructed, including its stable
ID and complete released trading identity. Its ID and descriptor fingerprint
must correspond exactly to the instruction. MARKET requires explicit null price;
LIMIT requires one exact price whose currency equals the canonical instrument
trading currency. TIF and session are mandatory. No generic compatibility
matrix or new timestamp exists.

Projection has exactly eight nested keys and is JSON-safe. Every nested source
is revalidated. Deleted or altered sources, string subclasses, equality spoofs,
state/binding attacks, cross-source contradictions, and stale top-level identity
raise `ExecutionPlanningCorrespondenceError`.

## Scope

The specification is complete intent but is non-executable and unauthorized.
There is no capability validation, broker mapping, broker request, submission,
routing, acknowledgement, live status, fill, cancellation, persistence, or
reconciliation behavior. No-action still terminates before specification.
