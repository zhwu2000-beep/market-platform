## Scope

V0.50.0 adds a deterministic, result-only local JSON artifact for one
`HistoricalReplayExecution`:

- strict typed serialization and public-model reconstruction;
- production result fingerprinting;
- canonical semantic integrity verification;
- atomic local save, verified load, and intention-revealing verify APIs;
- focused artifact and filesystem errors.

Final review corrections make default non-overwrite publication atomic through a
same-directory create-if-absent hard link, keep competing targets unchanged,
preserve primary save exceptions when temporary cleanup also fails, and classify a
stale specification fingerprint as an artifact integrity error.

## Schemas and Payload

- artifact: `historical_replay_artifact/v1`
- typed result/fingerprint: `historical_replay_result/v1`
- integrity: `historical_replay_artifact_integrity/v1`

The serialized envelope contains execution provenance and run fingerprint, one
typed result payload, its result fingerprint, and the integrity block. The complete
result is not duplicated.

The reader accepts v1 only, requires exact known fields, rejects unknown fields,
normalizes aware datetimes to UTC, reconstructs tuples and enums, and invokes public
constructors so domain validation runs again.

## Tagged Evidence Contract

`StrategyEvidence.observed_value` is tagged as string, integer, float, boolean,
datetime, or null. ISO-looking strings remain strings, datetime values remain aware
UTC datetimes, and booleans never decode as integers. Floats are finite and
canonical; signed zero is represented as `0.0`.

## Fingerprints and Integrity

- The v0.49.0 run fingerprint is preserved unchanged and identifies execution
  inputs and resolved facts.
- The production result fingerprint covers the complete typed result payload and
  is distinct from the benchmark result fingerprint family.
- The semantic checksum covers every envelope field except its own checksum value.
  Mapping order, formatting, line endings, and final-newline differences do not
  affect verification; semantic edits do.

The checksum detects accidental corruption and inconsistent edits. It does not
provide authenticity, signatures, or non-repudiation.

## Filesystem Behavior

Files are deterministic compact sorted JSON, UTF-8 without BOM, with one final LF.
Missing parent directories are created. Existing targets are refused unless
`overwrite=True`. Writes use an fsynced temporary file in the destination directory
and atomic replacement; cleanup is attempted after failure. Loading always verifies
and preserves native filesystem exceptions.

## Compatibility Guarantees

- `run()`, `run_with_specification()`, and `run_execution()` are unchanged.
- `HistoricalReplayResult.to_dict()`, step/summary models, and CLI table/JSON/CSV
  schemas are unchanged.
- Observation, dataset, specification, run, strategy-configuration, research, and
  benchmark fingerprint families are unchanged.
- No artifact work runs on the legacy replay or benchmark path.

## Limitations and Non-Goals

The artifact stores provider and dataset fingerprint but not OHLCV rows, so it
cannot recover data or rerun the calculation. V1 loads the complete JSON document
and is limited to locally generated, trusted-size files.

Excluded: dataset artifacts/locators, repositories, databases, cloud storage, CLI
artifact commands, software-revision discovery, experiment/workflow systems,
signatures/encryption, untrusted-file resource limits, research migration,
portfolio/risk/execution, fingerprint optimization, and package-version changes.
