# v0.72.0 Daily Research Instrument-History Integrity Handoff

## Scope and API

The release adds a strict trusted mapping codec,
`TrustedInstrumentMappingRegistry`, lifecycle integrity evidence, a verified
result, and `IntegrityCheckedDailyTechnicalResearchWorkflow`. The seven
frozen exports are appended after the released 77-name research prefix.

`market-platform research analyze-verified` requires symbol, venue, and
instrument-mappings; it retains daily/Polygon/table defaults, strict aware
`--as-of`, singleton option rejection, and explicit output handling. JSON is
exactly `research` then `integrity`; the table retains 41 research rows and
adds 16 integrity rows.

New schemas are `trusted_instrument_mapping_document/v1`,
`trusted_instrument_mapping_registry/v1`, and
`daily_instrument_integrity_evidence/v1`. Only the registry and integrity
evidence add fingerprint families. Source, mapping, registry, original dataset,
and admitted dataset provenance are retained and revalidated.

## Validation and compatibility

Focused codec and integrity tests cover strict decoding, deterministic
registry identity, direct nested retained-state corruption, factory ownership,
exact creation-time resolution sealing, ticker reuse, stable trimming, and
snapshot/admitted correspondence. Validation gates are pytest, Ruff, mypy,
and `git diff --check`; the opt-in real Polygon smoke remains credential
controlled.

The implementation inventory contains the six authorized new files (codec,
integrity models/workflow, two focused unit suites, ADR, and this handoff) and
nine authorized modified files (daily analysis, research exports, CLI, export
and CLI tests, real-provider smoke, architecture, roadmap, and smoke docs).
The two additionally authorized compatibility files,
`test_daily_technical_research.py` and
`test_instrument_identity_mapping.py`, needed no edit because their existing
frozen-behavior assertions already cover the narrow refactor.
