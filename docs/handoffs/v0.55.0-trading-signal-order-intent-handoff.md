## Signal Contract

An instrument requires uppercase symbol and venue; qualified external symbols
containing `:` are rejected. A source requires an opaque ID and version plus an
optional repository fingerprint. Every signal requires a producer-owned,
case-preserved source event ID.

Targets are exact unsigned `Decimal` magnitudes with `long`, `flat`, or `short`
direction. Long/short require positive units and flat requires zero. Constructors
reject integers, floats, strings, bool, negative values, negative zero, NaN, and
infinity. Equivalent trailing-zero and exponent representations normalize to
one fixed-point string without rounding.

Signals require aware `generated_at`, `valid_from`, and `expires_at` timestamps,
normalize them to UTC, and enforce
`generated_at <= valid_from < expires_at`. Applicability is
`not_yet_valid`, `active`, or `expired` under the half-open interval
`[valid_from, expires_at)`, evaluated only at an explicit `as_of`.

## Identity and Conflict Semantics

The source fingerprint covers source ID/version/configuration. The signal
idempotency key covers source fingerprint plus source event ID. The signal
fingerprint covers complete canonical signal content.

- same idempotency key and signal fingerprint: `identical`;
- same idempotency key and different signal fingerprint:
  `conflicting_content`;
- different idempotency keys: `unrelated`.

The comparison helper classifies only; it performs no storage or deduplication.

## Policy and Order Intent

`ExactTargetPositionIntentPolicy` has one fixed methodology, version, empty
configuration, and deterministic fingerprint. Conversion accepts only an active
signal at a caller-supplied `as_of`.

The resulting factory-only `OrderIntent` retains the source signal and policy,
copies the exact target, records `decision_as_of`, begins validity at that
decision, and expires with the signal. Different decision instants create
different intent fingerprints. Temporal inapplicability raises
`TradingSignalNotYetValidError` or `TradingSignalExpiredError`.

Order Intent has no status and no account, current-position, transaction-side,
risk, broker, order-type, routing, submission, or fill semantics. Its dictionary
projection is a bounded JSON-safe identity summary.

## Boundaries

No application facade, external decoder, TradingView schema/webhook, HTTP,
authentication, ingress receipt, persistence, repository, queue, account,
portfolio, risk decision, execution plan, broker adapter, live trading, CLI,
Agent, or UI was added.

A future ingress adapter maps external symbols and timeframes into the canonical
domain. Delivery and authentication evidence remains a separate future receipt.
Future risk and broker layers remain strictly downstream of Order Intent.
